## Was sind Rat-Lab-Challenges?

Rat-Lab-Challenges sind praktische Übungen zur Cyber-Threat-Intelligence, bei denen Ihnen ein einzelnes Artefakt ausgehändigt wird – oft nichts weiter als ein Datei-Hash – und Sie daraus eine vollständige Angriffsgeschichte rekonstruieren sollen. Sie sind wichtig, weil die getestete Fähigkeit dieselbe ist, die über den Ausgang eines echten Vorfalls entscheidet: die Fähigkeit, aus einer unbekannten Binärdatei einen benannten Angreifer, eine Zeitachse und einen Eindämmungsplan zu machen. Wenn Sie jemals vor einem Alert ohne Kontext gestanden und sich gefragt haben, wo Sie überhaupt anfangen sollen, sind Rat-Lab-Challenges der Übungsplatz, auf dem Sie lernen, diesen Kontext schnell aufzubauen.

Der typische Aufbau ist bewusst einfach. Sie öffnen ein Challenge-Paket und finden eine Textdatei mit einem SHA256-Hash. Das ist alles. Keine Probe, keine Sandbox auf Ihrem Rechner, keine Hinweise außer einer kurzen Vorfallbeschreibung. Ausgehend von diesem Hash sollen Sie die Malware-Familie identifizieren, nachvollziehen, wie sie sich auf einem infizierten Host verhält, und die Infrastruktur eingrenzen, mit der sie kommuniziert.

Ein repräsentatives Szenario – entnommen aus einem viel geteilten Yellow-RAT-Lab-Walkthrough – beschreibt ungewöhnlichen Netzwerkverkehr in einem fiktiven Unternehmen, nachdem Suchanfragen mehrerer Mitarbeiter beginnen, auf unbekannte Websites umzuleiten. Ihre Aufgabe als Analyst besteht darin, den Vorfall abzugrenzen und eine feste Reihe von Untersuchungsfragen zu beantworten.

## Der Aufbau einer Rat-Lab-Challenge

Jedes Lab folgt grob demselben Muster: ein Briefing, ein Artefakt, eine Anreicherungsphase und ein Urteil. Diesen Rhythmus zu verstehen, ist die halbe Miete, denn er sagt Ihnen, wonach Sie suchen müssen, bevor Sie auch nur einen Browser-Tab öffnen.

| Phase | Was Ihnen übergeben wird | Was Sie liefern müssen |
|---|---|---|
| Briefing | Eine kurze Vorfallbeschreibung | Ein mentales Modell des Eindringens |
| Artefakt | Eine Hash-Datei (üblicherweise SHA256) | Identifikation der Malware-Familie |
| Anreicherung | Zugang zu öffentlichen Threat-Intel-Plattformen | Dateinamen, Zeitstempel, abgelegte Dateien, Netzwerk-IOCs |
| Korrelation | Mehrere sich überschneidende Berichte | Bestätigte Antworten plus Hinweise zur Behebung |

Die wichtige Mechanik hier ist **Triangulation**. Eine einzelne Quelle reicht selten aus. Starke Lösungen bestätigen jede Antwort über mindestens zwei oder drei unabhängige Plattformen – genau so vermeiden professionelle Analysten auch Falschmeldungen.

Wenn Sie die Plattform sehen möchten, die dieses Format populär gemacht hat: [CyberDefenders bietet einen rotierenden Katalog von Blue-Team-Challenge-Labs](https://cyberdefenders.org/), organisiert nach Schwierigkeitsgrad und Angriffstyp.

## Die sechs Fragetypen, denen Sie begegnen werden

Die meisten Rat-Lab-Challenges stellen zwischen fünf und acht Fragen und greifen immer wieder dieselben Archetypen auf. Wenn Sie das Muster einmal gelernt haben, können Sie mit einem Plan in jedes farbcodierte Lab gehen.

| Frage-Archetyp | Getestete Fähigkeit | Wo die Antwort üblicherweise zu finden ist |
|---|---|---|
| Name der Malware-Familie | Identifikation des Angreifers | Klassifizierung und Tags im Sandbox-Bericht |
| Häufiger Dateiname | Hostbasierte IOC-Jagd | Metadaten der Dateiversion („ursprünglicher Name“) |
| Kompilierungszeitstempel | Zeitachsen-Forensik | Kopfdaten der Portable Executable |
| Datum der ersten Übermittlung | Geschichte der Community-Erkennung | Übermittlungsverlauf der Probe |
| Abgelegte Dateien | Persistenz und Bereinigung | Verhaltensbericht zu Dateischreibvorgängen |
| C2-Server | Netzwerk-Eindämmung | Netzwerkabschnitt im Verhalten plus Domain-Reputation |

Zwei davon verdienen besondere Aufmerksamkeit. Der **Kompilierungszeitstempel** wird oft mit dem Erstfunddatum verwechselt; sie beantworten unterschiedliche Fragen. Die Kompilierung sagt Ihnen, wann der Autor die Binärdatei erstellt hat, während die erste Übermittlung sagt, wann die Verteidigungscommunity sie erstmals gesehen hat. Die Lücke zwischen beiden kann darauf hindeuten, wie lange eine Bedrohung unentdeckt geblieben sein könnte.

Die Frage nach dem **C2-Server** ist diejenige, die eine gute von einer großartigen Antwort trennt. Kopieren Sie nicht einfach eine URL aus einem Bericht. Pivotieren Sie darauf, prüfen Sie die Reputation der Domain und sehen Sie, ob mehrere Quellen übereinstimmen. Rat-Lab-Challenges belohnen diesen zusätzlichen Verifikationsschritt.

## Tooling: Ihr Toolkit für Rat-Lab-Challenges

Sie brauchen kein Enterprise-Budget. Der Stack, der fast jedes Lab löst, ist kostenlos, browserbasiert und schnell zu erlernen.

| Tool | Hauptverwendung | Typische Antwort, die es ermöglicht |
|---|---|---|
| Hybrid Analysis | Sandbox-Berichte und Verhaltensindikatoren | Malware-Familie, abgelegte Dateien, externe Systeme |
| VirusTotal | Multi-Engine-Erkennung und Dateimetadaten | Ursprünglicher Dateiname, Kompilierungszeit, erste Übermittlung |
| Bedrohungsberichte von Herstellern | Kontext aus realen Vorfällen | Dateipfade und beobachtete C2-URLs |
| Suchmaschinen | Pivotieren auf Hashes und Domains | Bestätigende Write-ups und Reputation |
| [MITRE ATT&CK](https://attack.mitre.org/) | Zuordnung beobachteten Verhaltens zu Techniken | Erklärender Kontext für Ihr Write-up |

**Hybrid Analysis** ist üblicherweise der beste Ausgangspunkt, weil die Sandbox-Berichte den Threat Score, die verwendete Umgebung und eine saubere Liste verdächtiger Indikatoren zeigen. **VirusTotal** ist die bessere zweite Station: Der Details-Tab offenbart Dateiversionsinformationen und Portable-Executable-Header – dort verstecken sich Dateinamen und Kompilierungszeitstempel. Hersteller-Bedrohungsberichte schließen die Lücken, wenn eine Sandbox ein Verhalten nicht beobachten kann – abgelegte `.dat`-Dateien im AppData-Ordner eines Benutzers sind ein klassisches Beispiel für etwas, das eine statische Engine Ihnen nie zeigen wird.

Eine kurze Liste von Gewohnheiten, die sich auszahlen:

- Arbeiten Sie immer vom Hash aus, nicht von einem Dateinamen, den jemand im Briefing erwähnt hat.
- Führen Sie eine Notiz mit jedem IOC, sobald Sie es finden; Sie werden sie wiederverwenden.
- Prüfen Sie die Reputation jeder Domain, bevor Sie sie als bösartig melden.
- Halten Sie fest, *wo* Sie jede Antwort gefunden haben – das macht Ihr Write-up glaubwürdig.

## Eine Rat-Lab-Challenge Schritt für Schritt lösen

Hier ist der Workflow, der Menschen konsequent zu einem vollständigen Antwortsatz bringt, ohne zurückzuspringen.

| Schritt | Aktion | Häufiger Fehler, den Sie vermeiden sollten |
|---|---|---|
| 1 | Lesen Sie das Szenario zweimal und notieren Sie Branche und Symptome | Direkt zum Hash springen |
| 2 | Fügen Sie den Hash in eine Sandbox-Plattform ein | Stattdessen nach einem Dateinamen suchen |
| 3 | Identifizieren Sie die Familie und notieren Sie den Erkennungswert | Annehmen, ein niedriger Wert bedeute sauber |
| 4 | Wechseln Sie zu einer zweiten Plattform für Dateimetadaten | Bei einer Quelle stehen bleiben |
| 5 | Jagen Sie die abgelegte Datei und ihren vollständigen Pfad | Nur die Erweiterung melden |
| 6 | Extrahieren Sie die C2 und prüfen Sie dann ihre Reputation | Einen Memory-String als bestätigt behandeln |
| 7 | Gleichen Sie die C2 mit einer dritten Quelle ab | Nach zwei Treffern absenden |
