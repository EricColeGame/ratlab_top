## Why the Rat Lab Walkthrough Matters for Blue Teams

You are handed a single file hash and expected to explain an entire intrusion. That is the daily reality of cyber threat intelligence (CTI) work, and the Rat Lab walkthrough is one of the fastest ways to rehearse it before the stakes are real.

If you can trace a suspicious hash to a malware family, a dropped payload, and a live command-and-control (C2) server using only public reporting, you can write the detections that stop the next incident. This Rat Lab walkthrough breaks the CyberDefenders Yellow RAT challenge into repeatable steps, so the workflow sticks the next time a real alert lands in your SOC queue.

## What the Yellow RAT Lab Scenario Asks You to Solve

In the scenario, a routine IT security check at GlobalTech Industries flags abnormal network traffic coming from multiple workstations. Employees report that their search queries are being redirected to unfamiliar websites. You receive a single artifact — a text file named `hash.txt` containing the SHA256 hash of the suspected malware — plus six questions to answer.

The point is not to "beat" the lab. It is to demonstrate a repeatable investigation path that a junior analyst could hand off to an incident responder without losing context.

### The Initial Clue You Are Given

The hash is your only starting point, and that constraint is intentional. In a real engagement you rarely get a full forensic image on day one — you get an indicator and a deadline. Community reports from analysts who have finished the lab note that the sample has an existing sandbox report from mid-2022, which means much of your early work is reading rather than reversing.

## Prerequisites and Tools for This Rat Lab Walkthrough

You do not need malware analysis experience, a disassembler, or a paid subscription. You do need three browser tabs, a notes file, and the discipline to record where each answer came from.

| Tool | Best For | Where Answers Hide |
|---|---|---|
| Hybrid Analysis | Sandbox behavior reports and dropper activity | Falcon Sandbox reports; Suspicious Indicators → External Systems |
| VirusTotal | File metadata, PE headers, community detections, URL reputation | Details tab; Behavior tab → Network Communication |
| Red Canary Intelligence | Curated reporting on known malware families | Published threat reports with observed indicators |
| Google / open-source research | Filling gaps and confirming vendor naming | Vendor blogs, research posts, community write-ups |

A few setup habits pay off immediately:

- Create free accounts on the analysis platforms so you can search historical reports.
- Keep a running table with columns for question, source, and evidence.
- Never submit the same hash to a public sandbox if your lab rules forbid sharing — most CTI challenges are fine with it, but check first.
- Use the browser's find function aggressively; long sandbox reports hide indicators deep in nested sections.

Once those tabs are open, the Rat Lab walkthrough becomes a reading comprehension exercise more than a technical one.

## Phase 1: Identify the Malware (Questions 1–4)

Start with Hybrid Analysis. Paste the hash into the report search and open an existing sandbox report for the sample — the Windows 7 32-bit run with a threat score in the mid-90s is the one most community reports point to. Within that report you will find the malware family that gives the lab its name, plus a linked third-party intelligence report worth bookmarking for later questions.

From there, pivot to VirusTotal and search the same hash. The Details tab becomes your primary workspace for the next three questions.

| Question | What You Need | Where It Lives |
|---|---|---|
| 1. Malware family | The family name behind the abnormal traffic | Hybrid Analysis sandbox report and linked vendor reporting |
| 2. Common filename | The name the sample typically ships as | VirusTotal → Details → Signature info → Original Name |
| 3. Compilation timestamp | Build time of the executable | VirusTotal → Details → Portable Executable Info → Header |
| 4. First submission date | When the community first saw the sample | VirusTotal → Details → History → First Submission |

Two of these answers are easy to miss. The common filename sits under the File Version Information header rather than in the detection list, and the first submission timestamp lives near the top of the Details tab in the History block — not in the behavior data. Scroll slowly and read the subheadings.

Understanding *why* each answer matters makes it stick. A compilation timestamp hints at how long the tooling has existed and whether you are dealing with a fresh build. The first submission date tells you how long the sample may have been circulating before anyone noticed. Both feed directly into an incident timeline.

## Phase 2: Scope the Dropped Payload and C2 Server (Questions 5–6)

The last two questions move from static metadata into what the malware actually does. VirusTotal may not carry the artifact data you need here, so switch to the linked Red Canary intelligence report you found in Phase 1.

That report lists the `.dat` file the sample writes into the user's `AppData` folder — the persistence-adjacent artifact you would hunt for across every other workstation on the network. The same section typically names the C2 URL the sample reaches out to, which answers Question 6.

| Question | What You Need | Where It Lives |
|---|---|---|
| 5. Dropped `.dat` file | Filename of the payload written to AppData | Red Canary report (not always present on VirusTotal) |
| 6. C2 server | The URL or domain the sample beacons to | Red Canary report, then confirmed on VirusTotal and Hybrid Analysis |

Do not stop at one source for the C2 answer. The best habit this Rat Lab walkthrough teaches is triple confirmation.

## The Triple-Confirmation Habit

Any single source can be wrong, stale, or mislabeled. When three independent platforms agree on the same indicator, your confidence in that indicator — and in the detection rule you build from it — rises sharply.

| Source | Evidence Type | What It Confirms |
|---|---|---|
| Red Canary | Analyst-written incident report | Named C2 URL and the dropped artifact |
| VirusTotal | Static strings plus URL reputation lookup | The same URL as a memory-pattern domain, with vendor detections |
| Hybrid Analysis | Sandbox telemetry | The URL listed under External Systems with reputation context |

Community reports consistently highlight this triangulation as the single most transferable skill in the lab. In production, you will rarely get three sources — but the instinct to look for a second opinion is what separates a solid indicator of compromise (IOC) from a guess.

A realistic time budget for a first attempt looks like this:

| Phase | Typical Time | Deliverable |

| Setup and hash lookup | 5–10 minutes | Malware family identified |
| Static metadata | 10–15 minutes | Filename, timestamp, first submission |
| Behavior and IOC pivot | 15–20 minutes | Dropped file, C2 server |
| Write-up and verification | 10 minutes | Confirmed, sourced answers |

Most analysts finish somewhere between 40 and 60 minutes on a first run and closer to 20 minutes on a repeat attempt with the same methodology.

## Common Mistakes to Avoid

- **Answering from memory instead of evidence.** Every answer should be traceable to a specific tab or report section.
- **Skipping the Red Canary report.** Without it, the dropped `.dat` file is nearly impossible to resolve.
- **Confusing the compilation timestamp with the first submission date.** They are different fields in different sections of VirusTotal, and they tell different stories.
- **Ignoring URL reputation.** Checking the C2 domain against VirusTotal adds context that strengthens your final report.
- **Rushing the write-up.** A walkthrough is judged on the reasoning as much as the answers.

If you want the official challenge set and scoring rules, the [CyberDefenders training platform](https://cyberdefenders.org/) is the authoritative source; other labs on the site use the same hash-first format and reinforce the same pivot skills.

## FAQ

**Is the Rat Lab walkthrough beginner-friendly?**
Yes. If you can search a file hash and read a report, you can complete it. The challenge rewards careful reading far more than reverse-engineering skill, which is why it is often recommended as an entry point into CTI work.

**Do I need paid accounts for the tools used in this Rat Lab walkthrough?**
No. Free tiers on Hybrid Analysis and VirusTotal cover everything the six questions require. The third-party intelligence report referenced in the lab is publicly available.

**How long does the Yellow RAT Lab take?**
Community reports suggest 40–60 minutes for a first attempt, including reading time. Once you know the pivot order, a second run takes roughly 20 minutes.

**What skills does the Rat Lab walkthrough actually build?**
Hash pivoting, static metadata interpretation, sandbox report reading, IOC extraction, and the source-correlation habit that turns a single indicator into a defensible incident finding. Those are day-one SOC and CTI skills.

Finish the lab, then write your own summary as if a teammate had to act on it. That final step is where the Rat Lab walkthrough turns from an exercise into a habit.
